2. Анализ SFInspector

Важно: SFInspector — специализированное ПО для инспекции газового оборудования. Точной публичной документации по его архитектуре нет. Информацию нужно получить у заказчика или поставщика ПО.

Возможные варианты СУБД у SFInspector

Наиболее вероятные варианты (типично для российского ПО в этой области):
  • MS SQL Server — самый частый выбор для Windows-ориентированных систем
  • PostgreSQL — всё чаще встречается в новых версиях
  • Oracle — реже, но возможно в крупных инсталляциях
  • SQLite / Firebird — для небольших инсталляций

3. Варианты интеграции с SFInspector

Выбор варианта зависит от того, что доступно в SFInspector. Расположены от предпочтительного к запасному.

РЕКОМЕНДУЕТСЯ

Вариант А: API SFInspector (если есть)

Суть: SFInspector предоставляет REST/SOAP API для получения данных о внештатных ситуациях.

  • Наш модуль запрашивает данные через API по расписанию или по событию
  • Нет прямого доступа к БД — безопасно, не нарушаем работу SFInspector
  • Поставщик SFInspector гарантирует стабильность интерфейса
  • Легко поддерживать при обновлениях SFInspector

Когда применим: если в SFInspector есть API и он документирован.

Вариант Б: Прямое чтение БД SFInspector

Суть: Наш модуль подключается к БД SFInspector и читает нужные таблицы напрямую (read-only).

  • Создаём отдельного пользователя БД с правами только на чтение
  • Пишем SQL-запросы к нужным таблицам
  • Данные копируем в свою БД для анализа
  • Не нагружаем SFInspector — только чтение

Когда применим: если API нет, но есть доступ к схеме БД и разрешение от владельца SFInspector.

Риск: При обновлении SFInspector структура БД может измениться. Нужен договорённость с поставщиком о уведомлениях.

Вариант В: Файловый обмен (Excel/CSV)

Суть: SFInspector экспортирует данные в Excel/CSV, наш модуль их читает (как в исходном BRD).

  • Самый простой и безопасный вариант
  • Не требует интеграции с БД или API
  • Работает с любой версией SFInspector
  • Легко тестировать и отлаживать

Когда применим: если API и прямой доступ к БД невозможны. Это резервный вариант, с которого можно начать пилот.

Вариант Г: Общая папка (watch-folder)

Суть: SFInspector автоматически складывает файлы в общую папку, наш модуль её мониторит и забирает новые файлы.

  • Полуавтоматический режим — без участия диспетчера
  • Не требует API или прямого доступа к БД
  • Нужна настройка прав на папку в Windows

Когда применим: если SFInspector умеет автосохранение в папку.

Рекомендация: Начать пилот с Варианта В (файловый обмен) — это быстро и безопасно. Параллельно запросить у поставщика SFInspector информацию об API (Вариант А). Если API есть — перейти на него в этапе 5 BRD.

4. Рекомендуемый стек под Windows

4.1. Основной стек (.NET-ориентированный)

Backend: .NET 8 (C#) + ASP.NET Core

Нативный стек для Windows. Отличная поддержка MS SQL, интеграции с Active Directory, работы в корпоративной среде. Высокая производительность.

Нативно для Windows Open Source

Frontend: Vue.js 3 + Vuetify 3

Собирается один раз на машине разработчика, раздаётся как статические файлы. Не требует Node.js на сервере.

Open Source Офлайн-развёртывание

База данных: MS SQL Server 2022 (или та, что у SFInspector)

Если SFInspector работает на MS SQL — используем тот же экземпляр (отдельная БД). Если на другой СУБД — выбираем ту же для упрощения поддержки.

Требует лицензии Реестр РФ

4.2. Альтернативный стек (если команда на Python)

Если в организации уже есть Python-команда, можно использовать:
  • Backend: Python 3.11 + FastAPI
  • Развёртывание: IIS + HttpPlatformHandler (для Windows)
  • БД: та же, что у SFInspector
Минусы: менее нативно для Windows, сложнее с корпоративной поддержкой.

5. Развёртывание в air-gapped среде

Ключевое ограничение: На сервере нет интернета. Это значит:
  • Нельзя использовать nuget install, npm install, pip install на сервере
  • Нельзя тянуть обновления из облака
  • Все зависимости должны поставляться в комплекте

5.1. Стратегия поставки

  • Self-contained deployment (.NET): приложение собирается вместе со всеми зависимостями и runtime. На сервере не нужен .NET SDK
  • Локальный NuGet-репозиторий: все пакеты заранее скачиваются на машине разработчика и передаются на сервер
  • Frontend как статика: Vue.js собирается один раз, на сервер передаются только .js, .css, .html
  • Установочные пакеты: MS SQL, IIS, .NET Runtime — передаются через корпоративный репозиторий или на носителях

5.2. Обновления

  • Обновления приложения — через корпоративный канал (WSUS, SCCM или ручная передача)
  • Обновления ОС — через WSUS (внутренний сервер обновлений Windows)
  • Обновления зависимостей — только после тестирования на staging-среде

5.3. Что нельзя использовать

Исключаем из стека:
  • Docker Hub (нет интернета для pull)
  • Облачные SMTP (SendGrid, Mailgun) — только внутренний Exchange
  • Облачные хранилища (S3, Azure Blob) — только файловая система или SMB
  • Внешние CDN (jsDelivr, unpkg) — все библиотеки локально
  • OAuth через Google/GitHub — только AD или локальная аутентификация

Потоки данных

  • Вариант А (API): SFInspector API → наш модуль → наша БД → Vue.js
  • Вариант Б (прямое чтение): БД SFInspector (read-only) → наш модуль → наша БД → Vue.js

  • Аутентификация: Active Directory (корпоративная) или локальная БД пользователей

9. План действий

Следующие 2 недели — критически важны для определения окончательного стека.

Неделя 1: Разведка

  • День 1-2: Задать вопросы 1-4 (о SFInspector) — IT-отделу и поставщику
  • День 3-4: Задать вопросы 5-8 (об инфраструктуре и ИБ) — IT-отделу и ИБ
  • День 5: Задать вопросы 9-12 (о команде и процессе) — руководителю разработки

Неделя 2: Решение

  • День 6-7: Проанализировать ответы, выбрать вариант интеграции (А / Б / В)
  • День 8-9: Утвердить окончательный стек (с учётом доступной команды)
  • День 10: Подготовить тестовую среду (сервер, БД, доступ к SFInspector)

Далее — по BRD

  • Этап 1 BRD (Обследование) — получить примеры Excel-файлов
  • Этап 2 BRD (Согласование) — утвердить критерии классификации
  • Этап 3 BRD (Пилот) — реализовать на файловом обмене (Вариант В)
  • Этап 5 BRD (Развитие) — перейти на API или прямое чтение БД
Итоговая рекомендация:
  1. Начать с Варианта В (файловый обмен) — это быстро и безопасно
  2. Параллельно выяснить возможности API SFInspector
  3. Использовать .NET 8 + Vue.js + MS SQL как основной стек (если есть команда)
  4. Развёртывать как self-contained приложение на Windows Server + IIS
  5. Заранее согласовать всё с IT-отделом и ИБ
